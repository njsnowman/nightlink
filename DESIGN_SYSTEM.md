# Nightlink visual standard

Nightlink has two interfaces, selected in Settings > Interface. The terminal interface is the default for 0.8.28 and later (owner decision, issue #131). The rc.11 card design is retained as the alternate interface and must keep working unchanged.

## Terminal interface standard

Reference: the approved terminal mockups attached to issue #131 (main menu, Mesh Relay Chat, message path map, Radio Tools). terminal.css owns the tokens and shared components; terminal.js stores the preference and applies `data-interface="terminal"` or `data-interface="cards"` to the root element of the main window, detached direct messages and the startup lock. Terminal styles are scoped to `html[data-interface="terminal"]` so cards mode is not affected.

Palette. Use only the VGA 16-color tokens: `--t-black #000000`, `--t-blue #0000aa`, `--t-green #00aa00`, `--t-cyan #00aaaa`, `--t-red #aa0000`, `--t-magenta #aa00aa`, `--t-brown #aa5500`, `--t-grey #aaaaaa`, `--t-dark-grey #555555`, `--t-bright-blue #5555ff`, `--t-bright-green #55ff55`, `--t-bright-cyan #55ffff`, `--t-bright-red #ff5555`, `--t-bright-magenta #ff55ff`, `--t-yellow #ffff55`, `--t-white #ffffff`. The page background is black. Body text is grey; headings and names are white or bright cyan.

Semantic colors. Green means confirmed or healthy. Yellow or brown/amber means an action, a hotkey or a pending state. Red means an error or a destructive action. Cyan means information and links. Dark grey is reserved for borders, separators and decorative fill; it is not used for text that must be read on black. Text on any surface keeps a contrast ratio of at least 4.5:1.

Type. Monospace everywhere, from the system stack `'Cascadia Mono', Consolas, 'Lucida Console', monospace`. No web fonts. Cascadia Mono and Consolas include the box-drawing glyphs used in delivery lines and frames on Windows. Use one size step for text and one larger step for page titles; do not use negative letter spacing.

Frames. Panels are frames drawn with CSS borders: double borders for the main window of a page, single borders for secondary windows. The frame title sits on the top border (`[■] Title` or plain title) with the background color behind it. Corners are square. No shadows or glow except the flat one-cell drop shadow used by dialog windows.

Bars. The top menu bar is grey with the active page highlighted. Chat and map views use a blue (#0000aa) topic bar and a blue status bar with bracketed fields such as `[13:42] [NAME] [2:#channel] [Act: 3]`. The bottom function-key bar is grey with red key names. On the grey bars the red hotkey letter (#aa0000, about 3.4:1) is a marker only; the label it belongs to is black on grey and meets the 4.5:1 requirement.

Hotkeys. Hotkeys are shown as `[C]` with yellow brackets and letter. Single-letter hotkeys are active only when no text field has focus. Every hotkey has a visible clickable equivalent. On the grey menu, function-key and dialog key bars, the hotkey letter is black, bold and underlined: VGA red (#aa0000) on grey (#aaaaaa) measures 3.34:1, below the 4.5:1 minimum.

Logo. The main menu draws the owner-supplied NIGHTLINK logo (signal arcs over the i, dithered blue letters, extruded shadow, speed lines), converted to 240 x 39 VGA pixels by `art/ansi/make-logo-art.py` into `terminal-logo-art.js` and drawn as merged pixel runs, up to 960 px wide. Regenerate it with the script rather than editing the data. If the data module is missing, terminal-logo.js falls back to the chrome NIGHTLINK logo from terminal-logo.js (`chrome()`): 12-pixel letterforms with 3-pixel strokes drawn as half-cell pixels, a one-pixel-per-six-rows italic lean, a solid ramp of white and bright cyan to dark cyan above a sharp horizon, bright cyan to blue below it, and a dithered dark-grey drop shadow. `art/ansi/make-chrome.cjs` exports the same logo as CP437 ANSI.

Pages and lock (rc.7). Tables in page windows are text-mode listings: cyan header row with black uppercase labels, dotted row rules, blue row highlight on hover or focus, no avatar tiles. Activity rows are log lines prefixed with a yellow `»`. Section headings read `[ Heading ]` in yellow. The main menu has no separate band under the logo. The startup lock shows the logo above the unlock card when the window is at least 800 px tall and 700 px wide (height capped at 12% of the viewport), and hides the small brand line there.

Message path. In terminal mode the dialog is near full screen: the path line and a collapsed `[+] text map` at the top, a one-line summary, then the street map filling the remaining height beside a 320 px repeater column (stacked below 900 px). Street tiles are inverted and blue-tinted; the route beam replays every 6 s while open unless `prefers-reduced-motion` is set.

Settings and Radio (rc.9). Settings categories are a DOS menu: `[letter]` hotkeys assigned by terminal-windows.js (first unused letter of each label, `aria-keyshortcuts` set), active only when no text field or dialog has focus; the selected category is a cyan bar with black text. The Radio status card is black with a double blue frame; tool tiles are rows with a yellow `»`, cyan title, grey description and dotted rule; group headings are yellow with a `══` lead. An empty MRC window shows a decorative antenna (`aria-hidden`) below the `-!-` line that states the window is empty.

Header and start-up (rc.10). The header row under the menu bar shows each status and control as `[text]` with grey brackets and no icons; the connection field shows its evidence and state on one line; the local clock is hidden (the menu bar has one). terminal-boot.js shows a roughly four-second BBS dial-up introduction once per session: typed modem commands, a staged ANSI handshake, progress and the logo. The dial-up sequence is explicitly simulated; a separate radio line follows real transport and synchronization events. The approved 6.1-second modem-to-laser WAV plays by default, respecting explicit sound-off and quiet hours. The loading screen cannot dismiss until the media ended event; input cannot stop or skip active playback. Autoplay denial offers a start/resume prompt, and failed or stalled media has a bounded fallback. Keys and pointer presses are consumed; they can skip silent visuals but cannot truncate startup audio. Reduced motion uses a static loading screen while audio completes. It does not run under automation (`navigator.webdriver`) or when Settings > Start-up screen is off (`nightlink.bootScreen`). The installed version comes from the desktop shell; the web preview shows none.

rc.11 additions. Detached DM messages are MRC-style lines (CSS only): grey time, `<nick>` in cyan (own nick white with `>>> `), message text, `[n hops]`, and a `└─` delivery line coloured by state. Help topics are menu rows (cyan selected bar) and the article sits in a double frame; PgDn/PgUp move between topics. Settings > Sound pack offers Standard or Retro; Retro synthesizes short square-wave patterns (no audio files) for the existing sent, DM and mention sounds and plays a chirp when the radio synchronizes; existing mute and quiet-hours switches still decide whether a sound plays. Empty Nodes and Direct Messages pages show `aria-hidden` ANSI art. Keyboard: arrows move through the main menu and table rows, `/` opens search or the MRC command line. MRC: Tab completes nicks and `#channels` (cycling), `/whois <name>` prints stored contact facts, and lines that mention your name get a yellow edge and text.

BBS detail. MRC gives each nick a stable color from eight VGA colors that meet 4.5:1 on black (hash of the name), opens each window with `***` banner lines (window, topic, stored-message and node counts from local data), marks day changes with a yellow `───` line, and frames the pane headers as `[ WINDOWS ]` over a double rule. Dialog windows follow Turbo Vision: double frame, blue title bar, `[■]` close control on the left, a solid dark-grey drop shadow and a dithered blue backdrop. Buttons in dialog and page windows are flat blocks with a dark-grey shadow that disappears while pressed: secondary grey (#aaaaaa, black text), primary cyan (#00aaaa, black text), destructive red; buttons that contain card content (search results, hop cards, inbox rows) keep their own layout. ANSI maps are framed with box-drawing characters, show `N ▲`, a distance scale computed from the plotted bounds, and draw known segments with `─ │ ╱ ╲`.

Audit. `terminal-audit.browser.test.cjs` checks every page, Settings category, dialog window, the detached DM and the startup lock in terminal mode: text contrast of at least 4.5:1 (3:1 for large text) against the nearest opaque background, an accessible name on every visible control, and a visible focus ring for each Tab stop. Fields draw the focus ring on `:focus` and `:focus-within` (date fields focus an inner segment), and focus rings do not animate. New terminal screens must pass this audit.

Focus. Keyboard focus is a visible 2-pixel bright cyan outline, or an inverted cyan bar on list rows. Focus is never removed.

Buttons. Buttons are flat cyan blocks with black text; destructive buttons are red with white text. Disabled controls use grey text and keep their label.

Main menu and chat. The Overview page in terminal mode is the BBS main menu: logo, node status box, main menu hotkeys mapped to existing views, recent callers and today's counts drawn from local data. The Messages page in terminal mode is Mesh Relay Chat (MRC): window list, scrollback with `HH:MM <nick>` lines, delivery lines that open the existing message path map, node list and an input line with `/msg`, `/join`, `/me` and `/help`. These views reuse the existing data and send paths; they do not issue radio commands to render.

Text-mode windows. terminal-windows.js gives the Radio, Settings, Nodes, Network map, Activity, Direct Messages and Search pages a blue window title bar (`[■] NAME subtitle`) in place of the card page heading and a key line naming the shortcuts that work there; Help, which opens inside Settings, is titled HELP and is marked in the menu bar. Every dialog opened through the shared `#dialog` (Device Center, Propagation Monitor, Message path and others) becomes a text-mode window: a sticky blue title bar and a sticky grey key line (`Esc Close`, `Tab Next control`, `Enter Select`). The Message path dialog adds an ANSI path view above the street map: a sender-to-receiver line with resolved hops by name (green), ambiguous hops (yellow) and unknown hops by hash (red), and a character map that plots only located points and connects only consecutive known hops. A hop-count-only path is shown as a counted gap; no route is inferred.

The Network map page adds an ANSI node map above the street map, collapsed by default so the street map keeps its height: saved contacts and your radio that have advertised locations, marked `@` (your radio), `r` (repeater), `c` (companion) and `m` (room server), with a digit where several nodes share a cell. No links are drawn, because adverts do not report which nodes hear each other. The detached DM window uses a blue title bar for the contact heading, and the startup lock card carries a `[■] NIGHTLINK · STARTUP LOCK` title bar.

Pages not yet converted inherit terminal tokens, fonts and square frames through terminal.css and must remain usable at 760 x 560 and 1320 x 860.

Terminal chat readability: message bodies start on a separate, consistently aligned line below the sender. The Chat text selector changes only message bodies (Small 14px, Medium 16px, Large 18px; Medium by default), persists locally and synchronizes with detached DM windows. Technical details stay at the base size with semantic delivery colors; received hop summaries remain bright cyan on a bordered blue field. Cards mode and the startup lock do not use the chat text size.

Terminal chat map: the right side of MRC contains a compact OKI Mesh CoreScope live map instead of the node listing. Use a double blue ANSI-style frame, cyan border title and a quiet external-feed status line; no provider chooser, CoreScope navigation, packet list or settings appear there. The map is approximately 280 x 190px on desktop. At widths up to 1100px it sits above scrollback with a 140px map height and starts collapsed in a fresh compact window. Preserve the iframe across chat renders; unload it when collapsed, offline, hidden by provider preference, outside Messages or outside terminal mode. Map-only presentation is desktop-only and is applied only to the explicitly marked allowlisted CoreScope iframe. Keep map attribution. The remote page must signal readiness before the iframe is visible; external UI changes or timeouts must not expose the full CoreScope interface.

## Card interface (alternate)


Owner-approved reference: the Radio Tools panel in rc.11. This design remains available as the Cards interface for every existing page, dialog, menu and detached window.

Use the existing user-selected accent and black/console palette. Main content uses quiet bordered cards with 14-pixel corners; controls use 9-pixel corners; dialogs use 20-pixel corners. Surfaces have subtle contrast, not decorative console corner brackets or glow. Keep functional primary actions in the accent color and secondary controls visibly bordered. Destructive actions and delivery states retain their semantic colors.

Use a 4/8/12/16/24 spacing rhythm, aligned content edges and vertically centered control contents. Page and section titles use clear weight and restrained negative letter spacing. Supporting copy is readable and subordinate; respect enlarged text. Use matching thin SVG line icons, never a mix of decorative emoji and mismatched symbols for new interface actions. Every icon action needs an accessible name.

Group related actions under meaningful labels. The entire action card is the button. Use short descriptions when they clarify a choice. Put maintenance and destructive operations in a separate section with existing confirmation flows intact. Do not invent connection, signal or progress evidence for decoration.

nightlink-design.css is the final shared presentation layer in index.html, dm.html and security-lock.html. Its tokens are the source for new shared surfaces and controls. Component files own layouts and behavior; extend a shared style before adding one-off overrides. Keep the approved Radio Tools landing panel visually stable.

Validate representative Overview, Messages, Network, Contacts, Radio, Settings, dialogs and menus at desktop and compact sizes with enlarged text. Check keyboard focus, scrolling, long labels and outgoing/incoming distinction. Detached DMs and the startup lock must load the same shared layer. Never initiate radio activity simply to render a view or take a screenshot. Automated fixtures use synthetic radios; separate physical evidence from layout checks.

Submenus are included at every depth: contact options, message actions, sidebar tools, terminal, discovery results, inbox/outbox, identity comparison, import/export, confirmation dialogs and expandable sections. nightlink-design.js adds matching decorative line icons to existing action buttons and dialog headers while preserving their DOM controls, accessible names and event handlers. Do not create a separate appearance for deeper menu levels.

The main Radio landing page uses a live identity/status summary and three labeled groups of full-width action cards: device/setup, routes/discovery and observation/diagnostics. Keep export and hardware details in an expandable section. Reuse existing tool controls and preserve their state across navigation; opening this menu must not issue radio commands.
