# Nightlink 0.8.22-rc.7 — local candidate

Tracking: https://github.com/njsnowman/nightlink/issues/60
Changelog: [CHANGELOG.md](../CHANGELOG.md)
Source commit: 6a0c1e1f66299a1bb32a9ab3aac90f7c4aac540b

## Behavior

Channel messages (including Overview), main direct conversations and detached DM windows display up to three linked raster images per message. HTTPS PNG, JPEG, GIF, WebP and AVIF URLs and Giphy gif share URLs are recognized. Giphy IDs use a small animated rendition. Original text is retained; previews include source links and fixed-size display areas. Failed image loads keep an unavailable label and source link. No HTML from remote pages is embedded. Both window policies permit HTTPS image resources; no-referrer is set on preview requests and source links. No changes were made to radio transmission or stored message text.

## Validation

- Two message-media.test.cjs unit tests passed: supported URLs, exact Giphy host matching, punctuation, deduplication, count limit and rejection of unsafe schemes, credential URLs, local IP literals, SVG and ordinary pages.
- message-media.browser.test.cjs passed: channel and Overview rendering, retained mention tags, GIF/raster decoding, no-referrer attribute, failed-image link retention, detached-DM rendering at 530×600 and 130% text without outer overflow. Network and DM bridge were simulated.
- signal-console.browser.test.cjs passed existing message/DM layout and compact navigation checks.
- Private message-media-native-check.cjs passed against built app.asar in Electron 42.11.12 with an isolated profile: packaged media module/CSS loaded and an image decoded under native CSP. Simulated HTTPS image; no radio access.
- Windows x64 NSIS and portable builds completed.
- A point-in-time request for the sample Giphy ID's 200w.gif rendition returned image/gif. External service availability is not guaranteed.

## Limitations

Images require Internet and load directly from their hosts, which receive normal network requests. Only the URL travels over MeshCore. Arbitrary webpage previews, extensionless image endpoints, video and non-Giphy share-page resolution are not included. HTTPS image decoding uses Chromium; image downloads are not proxied or stored in history backups. Fixed preview boxes avoid late decoding shifts; failed previews may reduce row height. Existing physical backlog acceptance remains open in #49. Local candidate only; no stable release or tag published.
