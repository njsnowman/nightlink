# Nightlink 0.8.28-rc.2 diagnostic candidate

Issue: [#131](https://github.com/njsnowman/nightlink/issues/131). PR: [#132](https://github.com/njsnowman/nightlink/pull/132). Previous candidate: [rc.1](0.8.28-rc.1.md). [Changelog](../CHANGELOG.md).

## Scope

rc.1 plus fixes from an automated accessibility audit of the terminal interface:

- Hotkey letters on the grey menu, function-key and dialog key bars: VGA red `#aa0000` on `#aaaaaa` measured 3.34:1. They are now black, bold and underlined.
- The header breadcrumb separator measured 2.11:1 on black; it now uses the terminal grey.
- Search date fields showed no ring when focus moved to an inner date segment. Fields now draw the ring on `:focus` and `:focus-within`, and focus rings do not fade in.
- The embedded CoreScope and MeshMapper maps showed no focus ring when Tab moved into them: the host iframe matches no `:focus` selector once focus is inside the embedded document. terminal.js now marks the focused iframe (`term-frame-focused`) and terminal.css draws the ring. Found by the Windows CI run 41506471205 (`iframe#corescope-frame`); local Chromium did not reach the iframe until the audit served a stub page to external frames.
- New `terminal-audit.browser.test.cjs`, added to `test:browser`.

## Audit method and coverage

Headless Chromium at 1320 x 860, terminal mode, synthetic radio state:

- Screens: Overview (main menu), Messages (MRC), Direct Messages, Nodes, Network map (node map open), Activity, Search, Radio, the six Settings categories including Help, and the Device Center, Propagation Monitor and Message path dialogs. Also the detached DM window and the startup lock.
- Contrast: every visible element that owns text, against the nearest opaque background; 4.5:1, or 3:1 for large text. Disabled controls, SVG, map tiles and the decorative character maps are excluded. The character maps have text labels (`aria-label`).
- Names: every visible button, link, field, tab and summary has an accessible name.
- Focus: up to 25 Tab stops per page and 15 per dialog each show an outline or ring on the element or on an ancestor using `:focus-within`.
- Before the fixes: 194 findings (178 hotkey-letter contrast, 14 breadcrumb contrast, 1 date-field focus; 1 MRC input finding was a false positive because its ring is drawn on the input line). After: 0.

Limitations: automated checks only. No screen-reader session (NVDA or Narrator) has been run, and the audit does not cover the Cards interface, which is unchanged from rc.11.
