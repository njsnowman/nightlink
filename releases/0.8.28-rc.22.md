# Nightlink 0.8.28-rc.22 local candidate

Tracks [Contact Book #151](https://github.com/njsnowman/nightlink/issues/151), [connection recovery #150](https://github.com/njsnowman/nightlink/issues/150), [changelog](../CHANGELOG.md) and [Contact Book behavior and limits](../docs/contact-book.md). Based on primary rc.21. Queen City Con is excluded and unchanged.

Contact Book stores selected mesh identities and personal fields/photos independently of radio contacts. Includes linked identities, searchable selection, known-location coordinate and street maps, retained last-known coordinates, bounded observed channel/adverts history, separate export/merge import and an explicit radio-add action. Channel name matches are unverified; ambiguous names are excluded. Advert snapshots do not establish live presence. See the behavior document for retention, backup and attribution limits.

Connection header shows retry countdown/attempt, synchronization stage, conditional Retry and the last valid live RF RX-log timestamp. Command replies do not update the RF timestamp. RX-log support depends on firmware; missing evidence is not treated as a connection failure. Preserve active chat, draft, focus, reading position and map iframe. Startup saved-device controls retain ownership while active. The existing transport abstraction handles Bluetooth and USB; connected sync errors retry synchronization rather than opening a new connection.

Validation: `node --run test` passed 390 tests, with one existing Python-art wrapper skipped. Contact Book and recovery browser suites passed with synthetic radios. Startup navigation, connection layout, header controls, terminal follow/drafts/find/reply/conversation-tools suites passed. Terminal accessibility audit passed 24 screens, including Contact Book details/map/activity, editor and picker, plus detached DM and startup lock. Book layout checked in terminal and Cards at 1320 and 760 pixels. A pre-existing startup-navigation fixture lacked a radio identity and failed on rc.21 as well; the fixture now supplies the identity needed for per-radio draft storage.

No physical-radio connection, radio write/transmission, actual installer completion or installed-upgrade validation performed. Radio-add behavior was exercised through a simulated API payload only. Unsigned local candidate; no public release or production merge. Owner acceptance remains pending. Native packaged-interface checks and artifact provenance will be recorded after building.
