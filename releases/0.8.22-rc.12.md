## Changes

Add opt-in Settings → App lock enrollment for a password plus authenticator code, with eight single-use recovery codes. Startup loads a dedicated lock document before workspace/history/auto-connect scripts. Recovery codes replace the phone factor but still require the password. Disabling requires both factors. Enrollment must verify a six-digit phone code and saved-code acknowledgement. Credential material uses password-derived AES-GCM inside Windows safeStorage/DPAPI; no plaintext fallback. Main-frame-only security IPC, persisted attempt delays and TOTP-step replay prevention are included. Security is off by default and was not enabled on the user's profile.

## Boundaries and unresolved validation

This is a startup access gate, not encryption of existing message/contact files or JSON backups. It does not automatically lock idle/tray sessions or protect against same-user malware, administrators, client/profile tampering, or deletion of the opt-in settings file. Recovery codes cannot replace a forgotten password. The implementation has not received an independent security audit; see SECURITY.md before relying on it.

Installer design is unchanged from rc.10; actual wizard-page visual validation and full upgrade/uninstall remain pending because of the documented Windows helper failure. Existing physical backlog acceptance in #49 remains open. Local candidate only; no stable release/tag published.
