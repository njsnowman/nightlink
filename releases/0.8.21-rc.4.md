# Nightlink 0.8.21-rc.4 — local contact workflow candidate

Tracked in [#53](https://github.com/njsnowman/nightlink/issues/53), [PR #52](https://github.com/njsnowman/nightlink/pull/52); see [changelog](../CHANGELOG.md). Application source: cc9afe66857d119d872b32310f017578d7dd04e5. Later commits contain validation records only.

## Behavior

Channel contact cards and Send message re-resolve saved companion identities, previous sender links and unique advertised-name/nickname matches. A resolved contact opens one compact/native DM window directly, leaving the main page and selected conversation unchanged. Repeated actions reuse the existing peer window. Contact editor and inline identity setup use the same single-window behavior.

Unresolved/ambiguous sender names do not determine a public key. They remain on the named card with an inline one-time full-key setup; the saved-companion dropdown and separate Open DM action are removed. No recipient is selected by partial/fuzzy name.

Contact cards show a circular image, display/radio names, node type and identity readiness, last locally recorded received message, last advertised timestamp, stored outbound route, received-message count and escaped read-only notes. Editing/photo upload/full public-key details remain secondary. Advert timestamps are not presented as proof of availability. Browser preview serves all new theme/message assets.
