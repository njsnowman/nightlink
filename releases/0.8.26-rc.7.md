# Nightlink 0.8.26-rc.7 - Core and optional infrastructure inspection

Tracking [#109](https://github.com/njsnowman/nightlink/issues/109), [PR #110](https://github.com/njsnowman/nightlink/pull/110).

Main inspection reads name, TX power, coordinates and RF parameters in five mesh round trips. It does not probe optional firmware-specific settings. An optional-settings panel lets the operator choose one additional setting to read and merge into the inspected configuration. Staged form edits remain staged while an optional value loads. A failed optional read retains the previous core snapshot; expired or uncertain authentication still prevents writes.

Physical diagnosis in rc.6 confirmed six successful replies followed by a missing reply to the optional path-hash query. Previously that blocked all configuration and discarded earlier reads. This separation fixes that client behavior without guessing why the remote query did not reply. No automatic retry or RF configuration changes are introduced.

Regression coverage includes five-request core inspection without optional probes, single optional reads, core-snapshot preservation, staged-edit retention, and guest write controls. Final package and physical validation follow below. This remains a candidate until the open hardware acceptance items are complete.
