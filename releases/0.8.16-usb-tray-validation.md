# Nightlink 0.8.16 physical USB tray validation

Post-release check on 2026-10-16, tracked in [#40](https://github.com/njsnowman/nightlink/issues/40). Tested the released packaged app.asar from the 0.8.16 Windows build in an isolated profile with the matching Electron runtime.

User-authorized Heltec V4.3 OLED, firmware v1.17.1-d929643, USB COM23. Initial synchronization loaded 292 contacts, one channel and two queued messages. The main window was shown and closed through its normal tray handler. It remained hidden for 181 seconds. Six checks at 30-second intervals confirmed connected/ready state, zero disconnect events and successful telemetry reads; twelve battery events included normal background polling.

Quit exited the process. An independent serial-port open/close then succeeded on COM23 with DTR and RTS disabled and no bytes written, confirming the port was released. No mesh messages, adverts, firmware changes or radio configuration writes were initiated. Received messages were preserved in an importable local backup, excluded from Git. The production Nightlink profile was not modified.

This confirms a three-minute physical background-operation smoke test, not multi-hour endurance or Windows toast delivery. Reproduction: node usb-tray.physical.test.cjs <released app.asar> <matching Electron runtime> <explicit USB port>.
