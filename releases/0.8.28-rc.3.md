# Nightlink 0.8.28-rc.3 diagnostic candidate

Issue: [#131](https://github.com/njsnowman/nightlink/issues/131). PR: [#132](https://github.com/njsnowman/nightlink/pull/132). Previous candidate: [rc.2](0.8.28-rc.2.md). [Changelog](../CHANGELOG.md).

## Reported problem

Owner report on the installed rc.2, 2026-11-02: when the main window first loads, the card design is visible briefly before the BBS/ANSI main menu appears.

## Cause

terminal.css and terminal.js load in the document head, so terminal colors and fonts apply at first paint. The BBS main menu is rendered by terminal-menu.js, which runs at the end of `<body>` after the other application scripts. Until it runs, the card Overview (`#overview` and the page heading) is laid out and painted.

## Change

- When the terminal interface is active, terminal.js adds `term-boot` to the root element in the head. terminal.css hides the main content area, except `#bbs`, while that class is present.
- terminal-menu.js removes the class after it renders the main menu, or immediately when the menu is not shown.
- Fallbacks remove the class on window load and after 4 s, so content cannot stay hidden if the menu script fails.
- Cards mode never sets the class. The detached DM window and the startup lock have no main content area; the load fallback clears the class there.
