# NightLink 0.8.28-rc.53 local candidate

Tracks [saved Operation map views #221](https://github.com/njsnowman/nightlink/issues/221) and the [Unreleased changelog](../CHANGELOG.md#unreleased). This is an unpublished candidate for owner evaluation.

## Scope

Save each Operation's last map center and zoom in a separate local preference and restore it when reopening that Operation. Shared basemap and layer preferences remain separate. Existing Operations without a saved view retain the site-based initial map view. The saved viewport is not part of project exports or RF records.

Source commit: `7fa170e78501f5cfe8ea9827f47446311b7f2aa8`.

- Node test runner over the files listed in `package.json` `scripts.test`, with the dot reporter: passed 532 tests, 0 failed, 0 skipped. `npm` was unavailable in the shell, so the same Node test list was invoked through `process.execPath`.
- `node operations.browser.test.cjs`: passed Operation planning workflows, saved viewport isolation, and restore on returning to the same Operation; no radio calls.
- `node planning-maps.browser.test.cjs`: passed six map sources, attribution, layer state, local preferences, disposal, and compact/enlarged layouts in Cards and Terminal. Fixtures use synthetic data.
- `node verify-package.cjs`: matched 278 packaged source/runtime files and 4 installer inputs to the source commit and generated the local manifest and checksum list.
- Windows Setup installed into an isolated temporary directory and uninstalled; both steps returned success and the installed executable was removed.

The packaged application's startup could not be confirmed on this machine. A stable NightLink instance was already running; the candidate exited with code 0 because the app's single-instance lock handed off to the running instance. Retrying with an isolated temporary `APPDATA` profile had the same result. The stable app and its processes were left untouched. Run the candidate after closing NightLink to validate its startup in the owner environment.

Owner evaluation: the owner tried the local candidate and reported that the map view appears to have been saved. The specific operation-switch/restart sequence was not reported.

Browser checks use synthetic radio data. No physical-radio validation was performed; the map viewport feature does not issue radio commands.
