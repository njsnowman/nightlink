# 0.8.22-rc.25 — CoreScope slow-start preservation candidate

Tracking: [#77](https://github.com/njsnowman/nightlink/issues/77). [Changelog](../CHANGELOG.md).

Initial page loading allows a bounded 120 seconds. Offline events and frame errors retain local-map fallback. Explicit source choices, recovery cancellation and MeshMapper behavior are preserved. No radio protocol, profile migration or security-bridge behavior changed.

Validation: new slow-start synthetic browser test confirms the same frame survives repeated failed health checks and delayed packet appearance on Overview and echo. Existing fallback and recovery browser fixtures pass with health-advisory versus actual-frame-error semantics. MeshMapper browser regression and 10 relevant unit tests pass. Separately, a fresh isolated native app with health checks forced to fail retained the same live CoreScope frame for 40 seconds, received 215 WebSocket frames and displayed 213 packets / 1,569 nodes. This is live public-service evidence, not a physical-radio test. No normal profile or radio accessed. User installed-profile acceptance remains open.

Local candidate only. Existing stable gates remain open.
