# Nightlink 0.8.28-rc.8 diagnostic candidate

Issue: [#131](https://github.com/njsnowman/nightlink/issues/131). PR: [#132](https://github.com/njsnowman/nightlink/pull/132). Previous candidate: [rc.7](0.8.28-rc.7.md) (superseded before testing; its page-listing and startup-lock changes are included). [Changelog](../CHANGELOG.md).

## Reported problem

Owner report on 2026-11-03: in the Message path dialog the map is far too small; it should be more automated and visually appealing.

## Cause

In rc.4 to rc.7 the ANSI path view (path line plus a 14-row character map) was inserted at the top of the dialog's flex layout. The street map is the flexible element, so it shrank to about 720 x 150 px at 1320 x 860.

## Change (terminal interface only)

- The dialog opens at the viewport size minus 32 px. The street map fills the remaining height beside a 320 px repeater column (stacked below 900 px wide); at 1320 x 860 it is about 920 x 470 px.
- The path line stays visible; the character map is collapsed under `[+] text map`.
- The three summary boxes become one line; the reception, status and "How this path is known" rows are compact.
- Street tiles are inverted and blue-tinted so the cyan route stands out.
- Known route segments replay every 6 s while the dialog is open; nothing replays when `prefers-reduced-motion: reduce` is set.
- After the layout change Leaflet re-measures the map (`invalidateSize`).
- The layout keys on `data-term-window="Message path"`; the `route-map-dialog` class the first draft used is never added by the app.
