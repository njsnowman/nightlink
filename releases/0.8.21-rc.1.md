# Nightlink 0.8.21-rc.1 — local layout candidate

Tracked in [#51](https://github.com/njsnowman/nightlink/issues/51). Application source: 3f95a729e66c9b96605675932af694d0a58ca959. Later commits add tests and validation documentation only.

## Changes

Radio is a main sidebar destination containing existing device details, health, refresh, exports and advert tools. Contacts and Radio panels are hidden on initial Overview and available in their dedicated views. Overview uses a slim statistics strip and gives messages two thirds of the desktop workspace beside the map. At widths up to 1000px, the map collapses to a header and can expand to a 150px preview. Composer remains visible; history scrolls inside its panel. Settings no longer appends the device panel.

CoreScope starts at latitude 39.44, longitude -85.35, zoom 8, covering the Batesville–Cincinnati–Indianapolis area on Overview and Network. The deployed CoreScope app.js parseViewportHash and live.js initial viewport precedence were inspected on 2026-10-17; explicit hash lat/lon/zoom override its saved viewport. User panning remains available.

## Validation

overview-layout.browser.test.cjs passed: 760×560, 920×700, 1320×860 and 1500×950, compact/normal modes, 130% text; at least 150px message history with the map collapsed, composer in viewport, no outer page scrolling, expandable map, Radio tools, Contacts and retained messages. navigation.browser.test.cjs passed with 350 contacts and 20 channels. corescope.browser.test.cjs passed regional URL, iframe isolation, map source lifecycle, offline fallback and compact bounds using a remote fixture. overview-layout.native.test.cjs passed against built app.asar with Electron 42.11.12 at 760×560 and 1320×860, 130% text. smoke.test.cjs passed simulated GATT synchronization, messages, ACKs, history and reconnect after updating device/export actions to use Radio navigation. No physical radio or production profile was used for layout checks.

This is a local candidate, not a stable release. It is based on 0.8.19 and does not include the pending reconnect patch in PR #50. The unresolved reconnect/backlog investigation #49 remains open; no connection fix or new hardware validation is claimed. No radio settings, messages, contacts or history were altered by these layout tests.
