# Nightlink 0.8.26-rc.15 - Optional Internet map visibility

Tracks [#114](https://github.com/njsnowman/nightlink/issues/114). Settings > Data & updates > Map visibility independently shows/hides CoreScope and MeshMapper. Choices persist locally across restarts. Hidden providers lose their source actions and embeds; no new provider health/location requests are initiated for them. An already submitted location request may finish. Overview and Network fall back to the local Radio map, and #echo uses its local map when CoreScope is hidden. Existing Radio Tools/shared design and Echo commands are retained.

This is a prerelease candidate. Physical configuration, contact-removal, peer messaging/reactions, installer lifecycle/DPI and normal-profile lock acceptance remain tracked separately. No stable release or update-feed change is included. Validation and artifact provenance follow below.

Source checks: 291 unit tests and all seven configured browser suites pass. The new map-visibility suite covers all four choices, Overview/Network/#echo behavior, unloading a selected provider, hidden-provider location guards, local fallback, reload persistence and three Settings sizes with enlarged text. Desktop Settings screenshot inspected. Existing CoreScope and MeshMapper browser integration passes; CoreScope fixture expectations were updated to the already established zoom9 coordinate formatting and Overview default, without changing application defaults.
