## Changes

Add Radio Tools → CLI Terminal with explicit connected-companion or saved repeater/room target. Local firmware CLI requires companion protocol 14; older companions retain read-only built-ins. Remote login is matched by key prefix, remote commands use text type 1, and companion acceptance is distinct from a remote reply. Commands share the existing serialized connection and are not retried automatically. Terminal history/output are bounded and session-only; password entry is cleared and not persisted. Potentially mutating commands require explicit confirmation in the terminal.

Restore Add channel handlers in Messages, Overview, the expanded Conversations sidebar, and Radio Tools. The existing hashtag/private-channel form and radio readback logic remain in use.

## Limitations

Remote CLI reply protocol has no per-command reply ID. One pending operation and an unambiguous sender prefix restrict matching, but an unrelated CLI reply from the same node can still match. Subsequent output from the selected authenticated node is displayed while the terminal is open. Permissions, supported commands and login lifetime are enforced by firmware; readback of arbitrary CLI changes is not automatic. Logout clears companion connection tracking, not a guaranteed server-side credential revocation. History redaction is heuristic; use the dedicated password field. Full local CLI is unavailable on protocol13 firmware. No shell commands, scripts, persistent credentials or Line of Sight are included.

Existing physical backlog acceptance remains open in #49. This is a local candidate; no stable release/tag published.
