# Nightlink 0.8.15 release record

Tracked in [#33](https://github.com/njsnowman/nightlink/issues/33), [#35](https://github.com/njsnowman/nightlink/issues/35), [#37](https://github.com/njsnowman/nightlink/issues/37), and [#39](https://github.com/njsnowman/nightlink/issues/39). Implementation: #34, #36, #38.

USB companion connections share the Bluetooth protocol session, radio identity/history and recovery flow. Overview and Network default to an isolated online CoreScope frame with a radio-map alternative. Radio Tools provides manual local/flood adverts and signed contact sharing/import. Windows setup uses a black, cyan and ice blue theme with native installation-folder and shortcut controls.

## Compatibility

Windows x64; Electron and application dependencies are bundled. USB requires USB-companion firmware and a data-capable cable; the installer does not flash firmware or install a serial driver. Select USB cable in the Connect dialog and choose the radio's port. Bluetooth remains available. CoreScope requires internet and shows observer-collected traffic; message paths continue using radio data. Back up and close Nightlink before installing. Existing Meshline application data is retained; contact storage remains version 2. Private repository update discovery requires signed-in access to GitHub releases.

## Automated and packaged validation

- 105 Node tests passed, including 11 USB transport/security tests and existing Bluetooth/protocol/recovery coverage.
- Browser fake-GATT integration passed: synchronization, telemetry, channel send/receive, acknowledgements, retained history and reconnect; no page errors.
- Packaged seven-view navigation/layout checks passed at content sizes from 760x528 through 1320x860, both compact modes, with a 350-contact fixture and no outer scrolling.
- Packaged live CoreScope passed source switching, compact bounds, cross-origin isolation and absence of native bridges, including serial, in the remote frame.
- NSIS and portable targets compiled with electron-builder 26.15.3 and Electron 42.11.12. Actual installer welcome, destination-folder and shortcut pages were inspected; black backgrounds, cyan artwork and readable labels were confirmed. Back/Next and cancellation remained available. Preview was cancelled before installation. A theme callback build failure and low-contrast checkbox found during development were corrected before these artifacts were produced.

Commands: package Node test list; node smoke.test.cjs; node navigation.native.test.cjs <app.asar> <matching Electron runtime>; node corescope.native.test.cjs <app.asar> <matching Electron runtime>; node usb.native.test.cjs <app.asar> <matching Electron runtime> COM23; electron-builder --win nsis portable --config.compression=store.

## Physical radio evidence

User-authorized Heltec V4.3 OLED, firmware v1.17.1-d929643, COM23 (USB VID 303A / PID 1001). Source and packaged applications selected the USB port, completed synchronization (284 contacts, one channel, zero queued messages), read telemetry, disconnected and reconnected using the remembered port. Tests used isolated profiles, including nightlink-navigation-native-KDrdHX for packaged validation. No radio configuration changes or mesh transmissions occurred during USB testing.

M1 advert reception evidence is separately recorded in [m1-advert-completion.md](m1-advert-completion.md). Physical unplug, USB over-the-air delivery, and installer upgrade execution were not tested; simulated stream-end and protocol tests are not hardware evidence.
