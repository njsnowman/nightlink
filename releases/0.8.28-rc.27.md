# Nightlink 0.8.28-rc.27 local candidate

Tracks [startup first paint #161](https://github.com/njsnowman/nightlink/issues/161), [changelog](../CHANGELOG.md) and [design standard](../DESIGN_SYSTEM.md). Based on rc.26. Main app only; Queen City Con unchanged.

## Confirmed cause and correction

rc.26 restored the intro in Cards but loaded terminal-boot.js after the application/chat scripts. This allowed the main page to paint before the overlay existed. Existing tests checked the eventual overlay/audio gate without delaying those resources or observing earlier frames.

The existing logo and startup scripts now load at the beginning of the body, before application markup and scripts. The opaque ANSI frame mounts immediately, preventing an application frame from preceding it. Audio and actual-radio observers start after DOM initialization so sound/quiet settings and radio globals are available. Startup setting injection likewise waits until the view function exists. The audio-ended gate, chosen-page handoff, disable preferences, once-per-session, quiet hours, reduced motion and recovery paths remain. No radio configuration or transmission is introduced.
