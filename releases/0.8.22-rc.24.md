# 0.8.22-rc.24 — Remote map recovery candidate

Tracking: [#77](https://github.com/njsnowman/nightlink/issues/77). [Changelog](../CHANGELOG.md).

An isolated Windows app initially fell back to the local map while the public CoreScope service remained available. Retrying the embed received live WebSocket frames. The existing single-failure health policy could leave the selected remote map in fallback indefinitely.

Require two consecutive health failures before fallback; reset the failure streak after success. Allow 45 seconds for the initial iframe load. After fallback, recheck the selected remote provider every 30 seconds and restore its embed when reachable. Cancel retry callbacks and stale results on source changes, navigation and offline state. Explicit Radio map choice is retained.

Validation: new synthetic browser regression passed transient tolerance, automatic recovery, explicit Radio choice and navigation cancellation. Existing fallback browser fixture passed offline, service failure, source preference and echo behavior. Nine health/location/region unit tests passed. Public live service availability and isolated native embed packet receipt were checked separately from synthetic tests. No physical radio, credentials or normal profile were accessed. Stable release gates remain open. Local candidate only.
