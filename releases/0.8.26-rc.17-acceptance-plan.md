# Nightlink 0.8.26-rc.17 physical acceptance plan

Prepared October 31, 2026 for owner execution. This is a test plan, not evidence. Record each result in [hardware acceptance](0.8.26-hardware-acceptance.md) with local times, and keep physical results separate from simulated results. Candidate details are in [rc.17](0.8.26-rc.17.md); remaining gates are in [readiness](0.8.26-readiness.md).

Run the tests in the order below. Stop a test at the first unexpected result, record it as observed, and do not retry automatically.

## 0. Obtain and verify the candidate

1. Download artifact `nightlink-0.8.26-rc.17-windows-candidate` from [Actions run 41150693947](https://github.com/njsnowman/nightlink/actions/runs/41150693947). It expires November 14, 2026.
2. Extract it and verify both executables in PowerShell:

   ```powershell
   Get-FileHash .\Nightlink-Setup-0.8.26-rc.17.exe -Algorithm SHA256
   Get-FileHash .\Nightlink-Portable-0.8.26-rc.17.exe -Algorithm SHA256
   ```

   Expected Setup: `7e37f56007cb1e1395dae21fd9405289fd39ee87b57843990dcde7fc1e3d4846`. Expected Portable: `8e5441225b89864ccf4d9b8eb0c6a9340d35614729975886c3111070fb5943be`. Do not continue if either differs.
3. Optional: right-click each executable > Properties > Digital Signatures, and record whether a signature tab is present. This settles the signing status recorded as not verified.

## 1. Contact removal on the disposable V4 roster ([#104](https://github.com/njsnowman/nightlink/issues/104))

Target: MeshCore-SN0MAN V4 BLK, owner-designated disposable roster. SNOMAN HQ contacts are not selected.

Preconditions: export a Nightlink backup; quit the installed app through the tray Quit command; install rc.17 Setup over the current installation; connect to the V4 over Bluetooth and wait for Ready. Record the firmware version and the favorite labels shown before any removal.

Single removal first:

1. Choose one non-favorite contact. Record its full public key.
2. Contact card > More > Remove from radio > confirm.
3. Pass: the app reports the removal verified; a full-key search returns 0 matches; a Refresh and a reconnect still return 0; saved history and the contact card remain.

Bulk removal:

1. Open bulk removal from Nodes or Radio Tools and record the preview counts (non-favorites to remove, favorites preserved). Tick the acknowledgement and select Remove non-favorites for that preview only.
2. Leave the radio within normal range; ordinary advertisements may arrive during the run.
3. Pass: every selected contact is reported verified, with zero unverified operations; all recorded favorite labels remain after a Refresh and a reconnect.
4. If it stops, record the exact message shown. rc.17 includes the underlying lookup error in the message; that text identifies the failing step that rc.16 did not expose.

## 2. Direct message ACK ([#96](https://github.com/njsnowman/nightlink/issues/96))

1. Choose a peer that has recently been heard directly or with a short path; record its name, key prefix and last-heard time.
2. Send one authorized DM from the main window. Do not retry manually.
3. Record the final state (Recipient acknowledged, or unconfirmed), whether the completion sound played, and whether the peer received the message.
4. Pass: recipient ACK observed and peer receipt confirmed. An unconfirmed result is a failure for this check, not a pass; record it and stop.

Optional in the same session: with the DM window hidden, have the peer send a DM back and record whether the window is presented (#96), and whether a reaction from the peer renders as a chip (#94).

## 3. Installer lifecycle in Windows Sandbox ([#63](https://github.com/njsnowman/nightlink/issues/63))

Windows Sandbox requires Windows 11 or 10 Pro, Enterprise or Education with virtualization enabled. Enable it under Turn Windows features on or off > Windows Sandbox. Each Sandbox session starts clean and is discarded when closed. Sandbox has no Bluetooth or USB radio access, so these tests cover the installer and the application profile only.

Place the files in one host folder, for example `C:\NightlinkTest`: rc.17 Setup, and stable `Nightlink-Setup-0.8.24.exe` from the [0.8.24 release](https://github.com/njsnowman/nightlink/releases/tag/v0.8.24) (SHA-256 `c6cabdb61ed57fea5ff732cb6b8bbe97ddbc4378ee601a972e14a6188e88716d`). Save this as `nightlink-test.wsb` and open it:

```xml
<Configuration>
  <MappedFolders>
    <MappedFolder>
      <HostFolder>C:\NightlinkTest</HostFolder>
      <SandboxFolder>C:\NightlinkTest</SandboxFolder>
      <ReadOnly>true</ReadOnly>
    </MappedFolder>
  </MappedFolders>
</Configuration>
```

Clean install (fresh Sandbox session):

1. Run rc.17 Setup from `C:\NightlinkTest`. Record each wizard page, the default install folder and whether the SmartScreen prompt appears.
2. Launch from the Start menu. Pass: the app starts, Settings > Data & updates shows Installed version 0.8.26-rc.17, and no error dialog appears.
3. Uninstall from Settings > Apps. Pass: the uninstall completes and the application profile folder is retained (`deleteAppDataOnUninstall` is false).

Stable upgrade (new Sandbox session):

1. Install 0.8.24 and launch it. Create local state without a radio: change two settings, write a draft or note where available, and export a backup to the Sandbox desktop. Quit through the tray Quit command.
2. Run rc.17 Setup over 0.8.24.
3. Pass: rc.17 starts, the changed settings and local state remain, and Settings > Data & updates shows Installed version 0.8.26-rc.17.

Display scaling: in a Sandbox session, set Settings > Display > Scale to 100%, 150% and 200% in turn, or change host scaling if the Sandbox does not offer it. At each scale, open the Setup wizard and the main window. Pass: no clipped text, overlapping controls or unreachable buttons. Record which method was used.
