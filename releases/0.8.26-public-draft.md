# Nightlink 0.8.26 - Public release description draft

Unpublished review document. Current downloadable candidate is 0.8.26-rc.15; final stable source, artifacts and checksums have not been selected. See [readiness](0.8.26-readiness.md), [candidate evidence](0.8.26-rc.15.md) and [changelog](../CHANGELOG.md).

## Changes since 0.8.24

- Consistent shared design across workspace pages, Settings, dialogs, nested menus, detached DMs and startup lock. Radio and Radio Tools use grouped action cards with matching icons and responsive layouts.
- Device Center supports staged companion configuration, authenticated remote repeater/room administration and direct text-CLI USB setup. Changes are reviewed before applying, guarded against connection changes and checked by readback. Remote core inspection displays progressive results and bounded read recovery; optional queries remain separate. Hardware compatibility limits below apply.
- Independent CoreScope and MeshMapper visibility under Settings > Data & updates. Choices persist, disabled embeds unload and the local Radio map remains available, including #echo fallback. An already submitted location request may finish.
- #echo buttons for !test, !spam, !echo and !yolo preserve the composer draft and respect radio readiness/busy state.
- Single contact removal and previewed bulk removal preserve Nightlink favorites and local history/cards; verified radio readback and interruption reporting are retained. Physical acceptance below remains pending.
- Signal Rail, activity inbox and Outbox distinguish receive activity, sending, awaiting ACK, radio acceptance and recipient confirmation. Incoming activity remains independent of outgoing state.
- Main/detached chat reading-position memory, resizable Overview split and a local support-report preview with allowlisted operational metadata.
- Native DM teardown guards prevent late window events from sending through destroyed WebContents. Packaging now checks all explicit application assets to prevent features being omitted from newer installers.

## Evidence available for the candidate

291 unit tests, three additional installer structure checks and seven source/exact-package browser suites pass. Additional map-provider integration, isolated Windows protected-storage, 0.8.24 payload migration/restart, optional-lock migration/recovery, native reaction/Signal Rail and live update IPC/UI/cache checks pass. Test and Windows package CI jobs pass. Candidate package verification matches all 201 application assets and 26 required feature assets to source.

Physical evidence is narrower: normal installed Bluetooth synchronization and display, one rc.15 #testing broadcast accepted by the companion with owner-confirmed second-radio reception, and earlier remote administrator login/core inspection on the tested companion/Batesville pair. Synthetic transport and payload migration tests are not physical transmission/configuration or NSIS lifecycle evidence.

## Limitations requiring final disposition

- Physical configuration write/readback, direct infrastructure USB setup, role-specific compatibility, peer messaging/speaker/reactions and temporary-contact single/bulk removal acceptance remain pending. Do not claim comprehensive hardware compatibility.
- No disposable Windows account/VM is available. Clean install, older-version NSIS upgrade and multiple-DPI installer validation remain unverified. Historical same-version reinstall and post-uninstall profile retention passed with the recorded rc.5 payload.
- Normal installed optional-lock re-enrollment/restart/unlock remains owner-dependent. The optional lock gates startup and does not encrypt existing message/contact history or backups; see [security boundary](../SECURITY.md).
- Candidate Windows executables are unsigned. Final release notes must accurately state the signing status.
- CoreScope and MeshMapper require Internet and external service availability; local Radio maps remain available when hidden or offline, with downloaded street tiles only where supplied.
