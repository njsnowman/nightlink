## Change

## CoreScope investigation

Provider source [live.js](https://map.okimesh.org/live.js) awaits configuration and full node hydration before subscribing the Live view. [app.js](https://map.okimesh.org/app.js) paginates nodes sequentially without an API request timeout. In isolated reproduction delaying the first node response 15 seconds, 393 WebSocket frames arrived by 16.3 seconds while the UI showed zero nodes/packets. Counts cover all frames, not verified packet totals; payloads were not logged. A normal fresh run displayed 1,614 nodes by 5.8 seconds.

Normal installed rc.26 corroboration: after one explicit map reload, WebSocket HTTP101 and incoming type=packet frames were visible while the node-list request remained pending and Live view showed zero. Other provider API requests were also delayed. This confirms a provider initialization dependency in this observation, not every possible startup cause. No remote scripts were modified/injected. An upstream remedy would subscribe/buffer before hydration and bound request waits. Keep #77 open; page-load timings do not verify live readiness.
