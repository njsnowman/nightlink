# Nightlink 0.8.28-rc.30 local candidate

Tracks [chat follow #168](https://github.com/njsnowman/nightlink/issues/168), [changelog](../CHANGELOG.md) and [design standard](../DESIGN_SYSTEM.md). Based on rc.29; main app only. Queen City Con unchanged.

Terminal captured reading state against the newest message in memory before its DOM row existed. It therefore treated an active tail view as history and stopped following. Capture now checks the previously rendered tail window before replacement. Intentional history anchors remain preserved. Sending from history resumes the live end in Terminal, Cards and detached DM, with owner/conversation guards for asynchronous completion in the main window.

## Validation

Unit suite: 435 passed, one existing Python-art wrapper skipped. Browser checks use synthetic messages and a blocked or stubbed radio transport; they do not demonstrate physical-radio behavior. New regression covers repeated pre-render arrivals while typing, draft/focus retention, bounded rows, manual history anchors, own-send resume and conversation switching during a pending send. Cards and detached DM tests exercise own-send resume through their production renderer paths. Remaining regression and packaged evidence recorded below before download publication.

No installer execution, live profile changes or physical-radio validation. Unsigned local candidate; no public release or production merge.
