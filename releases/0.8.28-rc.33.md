# Nightlink 0.8.28-rc.33 local candidate

Tracks [Field Survey #173](https://github.com/njsnowman/nightlink/issues/173), [changelog](../CHANGELOG.md), [workflow/model limits](../docs/project-planner.md) and [design standard](../DESIGN_SYSTEM.md). Based on rc.32; feet, project studies and chat-follow retained. Queen City Con unchanged.

Field Survey adds a three-step right-panel workflow beside the existing map: choose an actual position, record an operator-entered direct test, then review planned-versus-observed point evidence. Device location is explicit with manual/map fallback; no radio commands or elevation retrieval run automatically. The existing street layer can fetch visible tiles when online. Immutable model snapshots, current/stale/unconfirmed/unmodeled states, follow-up priorities, local drafts and survey CSV/GeoJSON/HTML exports keep measured observations distinct from models. Current matched direct-path survey RSSI can join the explicit conservative calibration preview; radial/scenario results do not.

Database/backup format 5 retains survey data; older database writers are blocked. Imports accept formats 1–5. Site/path removal retains survey history; project duplication resets survey execution state. Export a pre-upgrade backup if a rollback copy is required. User measurements and source metadata retain their units/meaning; presentation remains in feet.

Validation and artifact provenance follow before candidate download. No physical-radio, actual device-location, installer completion/upgrade or live-profile evidence. Unsigned local candidate only; no public release/tag or production merge.
