# Nightlink 0.8.28-rc.54 candidate

Tracks the Overview chat expansion control update in [issue #218](https://github.com/njsnowman/nightlink/issues/218) and the [Unreleased changelog](../CHANGELOG.md#unreleased). This is a Windows x64 prerelease candidate approved by the owner for publication.

## Scope

The Overview chat panel action is labeled “Expand chat” and routes to the full Messages page. No radio commands or data changes were added.

## Automated validation

- `npm test -- --test-reporter=dot`: passed 532 tests, 0 failed, 0 skipped.
- `node messages-navigation.browser.test.cjs`: passed channel/direct-message navigation, search menu, escape handling, and compact bounds.
- Focused Cards-mode browser check: the Overview “Expand chat” control is visible and opens the full Messages page; no radio access.
- `npm run test:browser`: full browser workflow passed, including Overview/Cards layout, Focus Mode in both interfaces, Messages navigation, Terminal accessibility audit (146 screens), startup, map, and planning suites. Fixtures use synthetic data; no radio commands were issued.
- A separate legacy `node overview-layout.browser.test.cjs` diagnostic failed at 760 × 560 because it starts in default Terminal mode and measures the hidden Cards Overview. The current full browser workflow passed its Overview/Cards coverage.
- `npm run verify:package`: matched 278 packaged source/runtime files and four installer inputs to the source commit.
- Windows Setup installed to an isolated temporary directory, started with `--meshline-test`, and uninstalled successfully. The Portable executable also remained running for 8 seconds with `--meshline-test`. A temporary app-data profile was used; the existing Nightlink profile was untouched.

No physical-radio validation was performed. The change is a presentation label using existing navigation and does not initiate radio activity.
