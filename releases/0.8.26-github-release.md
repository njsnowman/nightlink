Nightlink 0.8.26 adds Device Center, radio contact removal, chat activity signals and a shared interface design.

Changes
- Device Center for staged companion configuration, authenticated remote repeater/room administration and direct text-CLI USB setup. Changes are reviewed before applying, guarded against connection changes and checked by readback. Remote core inspection shows progressive results; core reads recover from missed replies and consume late replies before the next command.
- Contact card > More > Remove from radio, and previewed bulk removal of non-favorites. Each removal is verified by an exact-key lookup on the radio. Saved messages, contact cards and Nightlink favorites are kept; interruptions report partial progress.
- Signal Rail, activity inbox and Outbox distinguish receive activity, sending, awaiting ACK, radio acceptance and recipient confirmation. Open delivery details stay synchronized with attempt progress.
- Independent CoreScope and MeshMapper visibility under Settings > Data & updates. Local Radio maps remain available when either is hidden.
- #echo buttons for !test, !spam, !echo and !yolo that keep the composer draft.
- Shared design across workspace pages, Settings, dialogs, nested menus, detached DMs and the startup lock. Radio and Radio Tools use grouped action cards.
- Reading-position memory in main and detached chats, a resizable Overview split and a local support-report preview with allowlisted operational metadata.
- Native DM teardown guards against late window events. Packaging checks all explicit application assets and records source provenance.

Validation
297 unit tests and twelve browser integration suites passed on Windows CI (run 41154908652). All 201 explicit package files match source. These automated checks use synthetic transports and are not proof of physical radio behavior.

Owner-reported physical checks on October 31, 2026, using the 0.8.26-rc.17 acceptance build, whose application files are identical to 0.8.26 except the version: single and bulk contact removal on a disposable Heltec V4 roster completed with all favorites kept; one DM to an in-range peer showed a recipient ACK and the peer received it; in Windows Sandbox, a clean install, an upgrade from 0.8.24 and display scaling at 100%, 150% and 200% passed.

Known validation limits
Direct USB setup, remote RF changes and other device roles have not been verified on hardware (#109). Normal-profile optional-lock enrollment and restart remain unverified (#87). Hidden-window DM presentation, the completion sound and peer reaction interoperability remain unverified (#96, #94). Both executables are unsigned. The optional app lock does not encrypt history or backups. Radio acceptance of a channel broadcast does not confirm remote delivery. Another client can consume the companion's finite pending queue. CoreScope and MeshMapper require internet access and external service availability.

Before upgrading, export a backup and quit Nightlink through its tray Quit command. Install Setup for the normal Windows installation, or use Portable; do not run both on the same profile/radio.
