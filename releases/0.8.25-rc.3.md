## Report and reproduced cause

Owner reports RX did not light for `!spam` replies in `#echo`. An isolated pre-fix model reproduction showed `receive` immediately after a reply, then `sending` after an immediate second update with unchanged history and an active outgoing message. Reapplying pending-send state replaced the single receive event. This reproduces a timing defect; it does not prove the timing of the owner's physical session.

## Change

Receive activity now has a separate per-conversation deadline from delivery state. RX can remain active while TX or ACK is also active. Each new incoming message extends the 2.6-second receive window; repeated rendering does not erase it. The RX color uses the selected display accent rather than an ACK/error color. Initial history, synchronization backlog, radio switching and disconnect do not replay receive indications. Reduced motion retains a steady active light.

No radio commands, retries or message parsing changes. The native DM view uses the same independent activity model.
