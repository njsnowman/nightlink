# NightLink 0.8.28-rc.57 candidate

Tracks [#207](https://github.com/njsnowman/nightlink/issues/207). [Changelog](../CHANGELOG.md#unreleased). Previous candidate: [rc.56](0.8.28-rc.56.md). Unpublished candidate for owner evaluation.

## Scope added since rc.56

- Stylesheet `:has()` selectors (57 uses in 15 files) are replaced by 28 generated state classes (`has-state-rules.js`, from `scripts/replace-has-selectors.cjs`). `has-state.js` keeps them current with a MutationObserver. The rules anchored on page ancestors made Chromium recalculate style for the whole document (about 4,100 elements) on every DOM insertion. `has-state.test.cjs` rejects new `:has(` in stylesheets.
- Terminal chat appends new messages to the existing transcript when the window is focused, followed to the end and otherwise unchanged. In all other cases it rebuilds as before, including when the window is unfocused, an unread boundary is set, Find is open or a message is selected.

## Validation (simulated)

- Benchmark, headless Chromium, 3,000 stored channel messages, 12 appended messages: style recalculation per DOM insertion fell from about 49 ms to about 0 ms. Median render time per received message fell from about 110 ms to about 6–8 ms.
- Computed style of the Cards Radio Tools dialog is identical before and after (width, padding, radius).
- `npm test`: 537/537. Local full `test:browser`: 98/98 at `c6b4c00`, including terminal-follow, terminal-live-follow and terminal-audit (146 screens).
- No physical-radio evidence.

## Physical evidence

None yet. Still required: chat responsiveness with a long history on the installed build; Radio Tools, Device Center and CLI dialogs and Settings pages look unchanged in both interfaces; plus the rc.56 items (#224 resync and re-add, startup sound, display options, sign-off screen).
