# Nightlink 0.8.14 release record

Nightlink 0.8.14 consolidates navigation and fits the application frame to its window.

- Four primary menu items: Overview, Messages, Network and Contacts. More groups Direct Messages, Search and Activity.
- Collapsible sidebar shortcuts show three channels and two recent DM contacts. Browse conversations provides searchable access to all channels, companion contacts and saved history.
- The main application frame has no outer vertical or horizontal scrollbar. Overview uses bounded panels, and the composer and Settings action remain within the viewport. Long history, directories, radio tools and Settings scroll inside their panels.
- Short-height windows receive additional overview message space. Full Messages view remains available for longer reading.

Compatibility

Windows x64. Back up and close Nightlink before installing. Existing %APPDATA%/Meshline data is retained. This update changes presentation and navigation, not the radio protocol. Internal panel scrolling remains necessary for content exceeding the visible area. Contact storage remains version 2 from 0.8.8; earlier version-1 clients may not open upgraded cards. Private-repository update discovery remains unavailable anonymously; open GitHub releases while signed in.

Validation

87 Node tests, browser layout checks, attention integration and fake-GATT messaging checks passed. A synthetic 350-contact/20-channel directory was tested across eight browser views, four window sizes, compact modes and large text. Isolated packaged Windows checks covered seven views at actual content sizes from 760x528 to 1320x860, searchable contact-card access, frame/panel bounds, composer access and usable message space. No production profile or physical radio was used. Installer-wizard upgrade was not exercised for this release.

Tracked in #32 and #30; implementation #31. Changelog: https://github.com/njsnowman/nightlink/blob/v0.8.14/CHANGELOG.md

Commands: package Node test list; node navigation.browser.test.cjs; node attention.browser.test.cjs; node smoke.test.cjs; node navigation.native.test.cjs <app.asar> <matching electron.exe>; electron-builder --win nsis portable --config.compression=store.

The first packaged check found too little overview message space at short heights. CSS was adjusted, both Windows targets rebuilt, and browser/native layout checks repeated successfully. Native tests now wait for resize completion and require at least 48 pixels of message content space; full Messages view measured at least 173 pixels in the smallest tested content size.
