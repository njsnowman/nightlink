# Nightlink 0.8.26-rc.17 - Removal verification, CLI recovery and Device Center review fixes

Tracks [#104](https://github.com/njsnowman/nightlink/issues/104) and [#109](https://github.com/njsnowman/nightlink/issues/109). This candidate addresses review findings against the 0.8.26 integration stack (PR #108 with stacked draft #110). Source changes are on branch claude/brave-allen-2y6ox8 in commits 72a5690, fa8f7e5 and b967854, based on the #110 head 5b9577b. See [changelog](../CHANGELOG.md) Unreleased entries.

This is a prerelease candidate record. The package has not been built. No physical radio operation, installer run, stable release, tag or update-feed change is included. Remaining public-release gates are in [readiness](0.8.26-readiness.md).

## Scope

- Contact removal ([#104](https://github.com/njsnowman/nightlink/issues/104)): after an acknowledged removal, verification now uses an exact-key CMD_GET_CONTACT_BY_KEY lookup that must return not found. rc.16 re-read the full contact list and required the frame count, announced count and parsed contact count to match exactly. Advertisements that add other contacts during the stream can break that predicate, and bulk removal read the whole roster per deletion. This is a candidate cause of the rc.16 physical bulk stop; the cause is not established, because rc.16 did not expose which predicate failed. Lookup failures now include the underlying error.
- Remote CLI read recovery ([#109](https://github.com/njsnowman/nightlink/issues/109)): after a retried core read, serialization is held until one late reply per earlier transmission is consumed, or until the reply budget expires and remaining replies are presumed lost. rc.16 used a fixed quiet window that could pass a late reply to the next command. If recovery is stopped or a session guard fails while a command is outstanding, the target is now quarantined and its session dropped. The firmware has no per-command reply ID; late-reply handling remains bounded best effort.
- Package provenance: verify-package.cjs refuses to record a manifest when packaged sources differ from HEAD. On pull-request CI it also records the pull-request head and base commits, because HEAD is a synthetic merge commit.
- Device Center ([#109](https://github.com/njsnowman/nightlink/issues/109)): local changes now update the Live, Radio page and Radio Tools views through a separate identity-updated event that does not reset sessions; the device readback is stored even when verification fails. A cleared numeric field is required even when the inspected value is 0. Inspection defaults to core settings only. Direct USB exports record the device key read during inspection instead of a placeholder, and staging a file exported from a different or unidentified device shows a warning. Integer fields and the retryable core-read allowlist are each defined once.
- Chat signal timers and refresh were measured and left unchanged: a local Node benchmark measured about 0.3 ms per Activity.update at 1,000 messages and 1.1 ms at 5,000; the history cap is 3,000 messages.

## Automated validation

All results below use synthetic transports. They do not establish physical delivery, contact removal or configuration behavior.

- npm test: 296 unit tests pass. New regressions for late-reply handling, stop-during-recovery quarantine, identity-updated events, core-only default inspection, cleared numeric fields and Direct USB export origin fail against the previous implementation and pass against this source.
- Browser suites: the eight test:browser suites (combined-ui, device-management, radio-tools-design, shared-design, submenus-design, radio-page, map-provider-settings, delivery-details) plus contact-deletion, bulk-contact-removal and radio-tools pass against source.
- Environment limitation: browser suites ran in a Linux container. The test files hard-code Windows Playwright and Edge paths, so a local preload shim outside the repository mapped them to the container's Playwright and Chromium. They have not been rerun on Windows for this source.
- radio-cli.browser.test.cjs times out in this environment on both the previous and current source. It is not part of test:browser. This is a pre-existing limitation, not a result for this candidate.
- verify-package.cjs was exercised only against a synthetic app.asar built from committed source: a clean tree records the manifest, an uncommitted packaged file is refused, and a pull_request event records head and base commits. No Windows package was verified.
- The import warning for files from a different or unidentified device has no automated browser test.
