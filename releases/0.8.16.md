# Nightlink 0.8.16 release record

Tracked in [#40](https://github.com/njsnowman/nightlink/issues/40); implementation [#41](https://github.com/njsnowman/nightlink/pull/41).

The desktop window closes to the system tray by default, preserving its renderer and transport session. Unread DMs and channel mentions appear in a combined icon badge and separate tray counts. Native notification clicks restore the matching conversation for the same radio. Settings adds close-to-tray control, local quiet hours and explicit disconnect-and-quit. Opening another instance restores the running window. A missing tray falls back to quit, and an unresponsive renderer cannot block quit beyond three seconds.

## Compatibility

Windows x64, installer and portable distributions. Back up and close Nightlink before installing. Application data remains in the existing Meshline profile. Close now means hide to tray by default; use Quit Nightlink in the tray or Settings to disconnect and exit, or disable close-to-tray. Desktop notifications remain opt-in and Windows notification settings apply. Quiet hours use local system time; equal start/end times mean all day. No automatic Windows startup registration or new runtime dependency is added.

## Validation

- 105 existing Node tests and nine tray/policy tests passed. The full suite initially passed with eight new tests; the final targeted suite passed all nine after adding unavailable-tray coverage. Tests cover midnight and all-day quiet periods, trusted main-frame IPC, stale-radio notification rejection, unread counts, close behavior, acknowledged quit and timeout fallback.
- Browser fake-GATT messaging integration passed synchronization, telemetry, channels, incoming/outgoing messages, acknowledgement, history and reconnect without page errors.
- Isolated packaged Electron tray checks passed actual Windows tray creation, hiding the main window without changing synthetic connection state, persisted quiet settings, incoming-DM sound/window suppression during quiet hours, unread IPC, duplicate-instance restore, notification-click routing using a mock native notification, renderer disconnect acknowledgement and process exit. Final fixture: nightlink-tray-native-XIsDgJ.
- Packaged seven-view compact navigation and bounds checks passed from 760x528 through 1320x860. Packaged live CoreScope checks passed dark rendering, source switching, bounds and remote-frame exclusion of all native bridges, including the new desktop bridge.
- NSIS and portable targets compiled with electron-builder 26.15.3 / Electron 42.11.12. The black/cyan installer theme is retained. All build inputs match the source checkout after text line-ending normalization.

Commands: package Node test list; node --test tray.test.cjs; node smoke.test.cjs; node tray.native.test.cjs <app.asar> <matching Electron runtime>; node navigation.native.test.cjs <app.asar> <matching Electron runtime>; node corescope.native.test.cjs <app.asar> <matching Electron runtime>; electron-builder --win nsis portable --config.compression=store.

No physical-radio commands were issued for this release. Windows toast delivery, physical radio endurance while hidden and installer upgrade execution were not tested. Simulated notification clicks and synthetic connection state are not physical-radio evidence.
