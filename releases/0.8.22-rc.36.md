## Change and scope

Use Electron's asynchronous Windows protected-storage provider for startup-lock reads and atomic writes. Require the API on Windows rather than silently falling back to an unavailable/legacy provider. Raise the Electron dependency floor to the tested 42.11.12 runtime. Preserve fail-closed behavior for unreadable settings; no reset, password bypass, plaintext fallback or automatic file replacement.

The original installed protected-settings file remains unreadable and unchanged. Its specific failure cause is not established. A minimal no-window synchronous probe failed restart, but an equivalent legacy store with a normal window passed. Consequently this candidate is storage hardening plus durable integration coverage, NOT proof that the old API caused the installed-file failure or that this change recovers it.
