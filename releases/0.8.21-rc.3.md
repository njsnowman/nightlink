# Nightlink 0.8.21-rc.3 — local message-layout candidate

Tracked in [#51](https://github.com/njsnowman/nightlink/issues/51), [PR #52](https://github.com/njsnowman/nightlink/pull/52). Application source: b34d20904ae7ad034cae5cc9325b2816dca2215b.

## Changes

Match the approved Signal Console message structure: circular contact image on the left; name, timestamp and boxed hop label on the identity line; text bubble below. Main Overview/Messages retain contact-card and channel path actions. Floating and native DMs share the header/bubble arrangement and preserve delivery actions. Received status is available via the bubble title rather than a second visible telemetry line; outgoing delivery status remains. Unknown paths and outgoing broadcasts are labeled explicitly without inferred hop counts. Photos use existing saved contact images; initials remain the fallback.

These are isolated/simulated UI checks, not physical-radio tests. Preview imagery uses illustrative messages and received metadata.

This is a local test candidate, not a stable release. The pending reconnect patch #50 is excluded, and investigation #49 remains open. The installed app and production history were not replaced or modified.
