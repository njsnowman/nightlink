# Nightlink 0.8.22-rc.15 — local candidate

Tracking: https://github.com/njsnowman/nightlink/issues/68
Changelog: [CHANGELOG.md](../CHANGELOG.md)
Source: ba8c462c3e26f02fd38b8a129b5b25d8cc981948

## Changes

MeshMapper uses Windows PC location at zoom12 on entry, source selection and Recenter, independently of radio coordinates. Enable cov_grid=1 green bidirectional coverage and fail_grid=1 red dropped-packet coverage. Preserve remaining provider layers and regional selection. A failed/denied/stale fix uses a labeled region center; no radio/IP fallback is presented as PC location. Windows provider runs hidden with bounded timeout, no persistent location storage, and trusted unlocked main-frame IPC only. Coordinates are sent to the selected MeshMapper embed. CoreScope and Radio map remain zoom9.

Main window starts maximized, including with saved compact density. Manual compact actions remain available during the session.

## Validation

- pc-location.test.cjs: three passed, covering stale/invalid fixes, provider errors and bounded execution, untrusted requests and concurrent request coalescing.
- meshmapper.browser.test.cjs and meshmapper-region.browser.test.cjs passed with synthetic PC positions distinct from radio location; zoom12/layer parameters, Recenter updates, unavailable-location labeling, region persistence, manual pan retention, frame isolation, compact dimensions and service/offline fallback. corescope-fallback.browser.test.cjs passed unchanged zoom9/default fallback behavior.
- meshmapper.native.test.cjs and meshmapper-region.native.test.cjs passed against built app.asar under matching Electron42.11.12. Synthetic PC location/service responses, isolated profiles, remote bridge isolation.
- overview-startup.native.test.cjs passed against source and built app.asar: maximized main window and Overview startup; saved compact density does not resize the native window on load.
- security.native.test.cjs passed against built app.asar: DPAPI enrollment, restart gating, recovery/disable and corrupt-state fail-closed in isolated profile.
- Real Windows location provider returned a valid current fix on this PC. Coordinates were not logged or stored in repository documentation. This does not establish accuracy or availability on other PCs.
- Windows x64 NSIS and portable builds completed.

## Limitations

Windows Location permissions/provider availability determine PC centering; unavailable position falls back visibly to region center. Red coverage appears only where MeshMapper has dropped-packet records. Remote source responses/coverage are independent of Nightlink. No physical radio or production profile accessed or changed. Prior installer visual-validation limitation and physical backlog acceptance in #49 remain open. Local candidate only; no stable release/tag published.
