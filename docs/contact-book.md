# Offline Contact Book

Tracks [#151](https://github.com/njsnowman/nightlink/issues/151). Primary Nightlink only. Queen City Con is unchanged.

Open Contact Book from the terminal main menu (`O`) or the Cards navigation. Save selected radio contacts using the searchable picker or Save to Contact Book in a contact card. Existing local card nickname, notes and photo are copied when present. Unsaved contacts are not automatically added.

The book has its own IndexedDB database, `nightlink-contact-book`, independent of radio profiles, contact-card storage and radio deletion. Entries contain personal name, alternate display name, call sign, email, phone, address, tags, equipment, notes, JPEG photo, optional personal coordinates and up to 20 full mesh identities. A full key belongs to one person. Additional identities can be selected using Link radio identity. Personal fields do not rename advertised senders in chat.

Each entry has a coordinate plot that requires no network, plus a Leaflet street map using Nightlink's shared street/offline-pack layer. Stored locations include their source and timestamp. Personal addresses are not geocoded. A newer advert without coordinates retains the previous known location and its original timestamp. Locations are neither continuous tracking nor evidence of present occupancy. The coordinate plot uses independent latitude/longitude axes and is not a distance or coverage estimate.

Activity is recorded prospectively for saved identities while the app is open. Channel observations come from messages received on the current radio's configured channels. They show observation time, radio-reported message timestamp, receiver key, channel and message text. A unique advertised-name candidate is labeled **name match; identity unverified**. Alternate personal names are not used for attribution. Duplicate or ambiguous advertised names are not assigned. Channel messages do not provide a full authenticated sender key; a name match is not proof of the transmitting identity. Queue messages can be older than the observation time. Loading local message history does not create observations.

Advert entries record newer advert snapshots read from the radio contact list, not confirmed live RF transmissions. No repeated activity is generated for an unchanged advert timestamp. Activity is bounded to the newest 300 observations per person and can be cleared separately. This is a local observation journal, not an always-on presence detector or a complete transmission history.

Add identity to current radio is an explicit confirmation action using the existing radio contact API. It writes public key, radio name and node type only. It does not restore routes, locations or personal data. Rendering, importing and exporting never send radio commands.

Use Export book for a separate JSON backup including photos, mesh snapshots, locations and activity. Workspace backups do not include this independent database. Book import previews the record count and merges missing entries; existing IDs or mesh-key owners are skipped without overwriting local notes. Validation occurs before a single atomic transaction. Maximum 40 MB of book data, 500 entries, 20 identities per entry, 300 observations per entry, 250,000-character JPEG data URLs and 50 MB per backup file. Photos are resized using the existing local image helper. Storage failures are reported and must not be treated as successful saves. Book data and exports are unencrypted local personal information.

Synthetic validation covers selected copies, photo/personal edits, independent persistence after radio-contact deletion and reload, unverified channel matching, ambiguity, duplicate messages, advert snapshots, retained last location, export/restore, atomic duplicate-key rejection, stale-editor history preservation, explicit radio-add payload and compact terminal/Cards layouts. No physical radio was connected or transmitted to validate these changes.
