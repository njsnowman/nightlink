# Terminal click-to-reply

Tracks [#143](https://github.com/njsnowman/nightlink/issues/143). Terminal message bodies now use the existing shared reply action, matching Cards. Clicking or pressing Enter/Space sets reply context and focuses the terminal composer. Channel replies use an ordinary `@[name]` mention; this is local reply context, not a new threaded radio protocol. The context stays inside the persistent composer during incoming-message renders. Switching selected reply replaces only the previously inserted mention, keeping the draft. Text selection and full drafts are preserved. Hop buttons continue opening the existing message map.

Browser validation with synthetic send/radio fixtures: click and keyboard reply, draft retention, context survival on render, recipient replacement, successful-send cleanup, full-draft limit, text-selection guard, conversation changes and hop gesture separation passed. Terminal regression browser checks and terminal accessibility audit across 19 screens passed. No radio transmission or user profile was used. Owner selected Clear Message: cyan usernames, white text and yellow own name. Included in [rc.19](../releases/0.8.28-rc.19.md).
